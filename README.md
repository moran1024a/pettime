# Pettime · Qt 桌宠

基于 [haichaojiang01-stack/pettime](https://github.com/haichaojiang01-stack/pettime) 重构的 C++17 / Qt 6 桌宠。保留原项目的图片素材和行为设计，以 Ubuntu 24.04 **X11** 为运行基线；公共代码和 CMake 构建兼顾 Windows；Windows 已通过 MSYS2 UCRT64 Release 编译、ZIP 打包及独立运行库加载验证，桌面交互和网络功能尚未完整验收。

## 构建与运行

Ubuntu 24.04：

```bash
sudo apt install build-essential cmake qt6-base-dev
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
./build/pettime
```

最低要求为 C++17、CMake 3.21、Qt 6.4。使用 Qt Core、Gui、Widgets、Network；测试额外使用 Qt Test。无需 QML、独立游戏引擎或直接的 X11 开发库。所有运行所需 PNG 均嵌入程序，不需要从源码目录启动。

默认构建测试。如只构建应用，在配置时增加 `-DBUILD_TESTING=OFF`。安装到个人目录：

```bash
cmake --install build --prefix "$HOME/.local"
```

安装后仍需要系统 Qt 6 共享库及其 X11 平台插件；单独复制可执行文件不代表已包含这些依赖。

Windows 一键编译并打包：双击根目录的 `build-windows.cmd`，或在 PowerShell 中执行：

```powershell
.\build-windows.cmd
```

脚本默认使用 `C:\msys64\ucrt64` 中的 GCC、CMake、Ninja、Qt 6、`windeployqt6` 和 `objdump`。自动配置 Release 并设置 `BUILD_TESTING=OFF`，编译后调用 `package-windows.ps1` 生成：

```text
build-windows\Pettime-windows-x64.zip
```

仓库只提交构建脚本、源代码和文档，不提交实际编译产物。默认的 `build-windows/` 已被 `.gitignore` 排除，其中的 EXE、DLL、ZIP 和构建缓存仅保留在本地。自定义输出目录时也应保持产物不被 Git 跟踪。

**分发这个 ZIP，完整解压后双击其中的 `Pettime-windows-x64\pettime.exe`。** 接收方不需要安装 Qt、MSYS2 或修改 PATH。不要单独复制构建目录根部的裸 EXE，也不要直接在压缩包浏览器内启动程序。

分发包包含 Qt 运行库、Windows 平台插件、其他 Qt 插件、GCC 运行库、递归收集的第三方 DLL，以及动态加载的 OpenSSL DLL；同时附带许可文本、说明和 SHA-256 文件清单。`qt.conf` 将插件路径设为包内目录。每次从全新临时目录打包，避免旧 DLL 混入；遇到未解析的非系统 DLL 或部署失败会报错，不生成新的成功包。成功后覆盖同名 ZIP，失败时原有 ZIP 可能仍在，应以脚本成功提示为准。

不构建或运行项目测试，不启动程序，也不安装软件或修改系统环境变量。配置、编译或打包失败时返回非零退出码；不带参数运行会在结束时暂停，方便查看结果。

如果工具链安装在其他位置，可设置当前终端的 `PETTIME_UCRT64`；第一个参数可指定输出目录（带参数时不暂停）。请使用同一套 UCRT64 编译器和 Qt，且不要复用其他工具链生成的构建目录：

```powershell
$env:PETTIME_UCRT64 = 'D:\msys64\ucrt64'
.\build-windows.cmd .\build-windows-custom
```

2026-09-29 使用 GCC 16.2.0、CMake 4.4.3、Ninja 1.13.2、Qt 6.11.2 完成构建和打包。实际 ZIP 已解压核查 DLL 依赖，并在仅含 Windows 系统目录的 PATH 下成功执行 `--version`；未运行项目测试，桌面交互和网络功能尚未完整验收。详见 [验证记录](VALIDATION.md)。

C++ 版本已替换旧 C# 实现，旧实现可从 Git 历史查看。

## 操作与行为

- 启动后自动爬行，重复启动会召回已有实例到鼠标所在屏幕中央。
- 左键拖动主宠物；右键打开菜单，控制大小、活跃程度、暂停、喂食、飞扑、召回和退出。
- 托盘也提供菜单及双击召回；桌面没有托盘时仍可通过宠物右键菜单和重复启动控制。
- 行走采用交替三足步态，动画按实际移动距离推进；待机时触角仍会活动。
- 鼠标靠近并移动时触发躲避；5 秒内连续追逐，从第三次躲避起有 12% 概率飞扑，此后每次增加 10 个百分点，最高 70%。5 秒无追逐后重新计数。
- 原菜单的“投喂一粒面包屑”始终投喂主实体。喂食成功增加 3–5 点好感度，上限 100。好感度影响兴奋动作和自发飞行概率。
- 双击成虫会先播放碾碎动画，随后成为总计 10 只若虫；双击若虫分裂为 8–12 只。实际生成数受数量上限约束。总数包含主宠物，默认最多 72 只；空间不足时，较早的群体若虫淡出，为新生若虫腾出位置。
- “数量上限…”可设置 1～72，立即生效并保存。降低上限时立即移除最早生成的超额普通实体并取消待生成队列；上限为 1 时主实体踩扁后恢复自身，不生成其他实体。
- “蟑螂列表…”显示所有实体的编号、名称、身份与状态。主实体编号固定为 1，名称固定为运行主机名，分裂和数量清理不会删除它；普通实体编号在本次运行中不重复。
- 列表支持普通实体重命名（最多 64 字符，清空恢复“蟑螂 #编号”）。名称仅在本次运行保留，新分裂实体不继承名称。
- “高亮定位”显示 3 秒黄色光圈和名称，装饰层不接收鼠标输入。右键宠物进入列表会选中对应实体，从托盘进入则选中主实体。
- 列表中的“播放投喂动画”可作用于任意自有实体，仅播放进食和开心动画，不结算好感度。动作结束后恢复原活动，成长时间正常推进；重复播放、进食、正面飞扑、踩扁和退场期间不可触发。
- 若虫每满一分钟长大一级，六分钟达到默认成虫尺寸。群体若虫会分散游走、避让同伴并随机起飞；规模增大时降低群体更新频率。
- 暂停、拖动和打开桌宠右键菜单会冻结主宠物的动作时间及动作帧；群体若虫独立活动，成长时间继续推进。GNOME 托盘菜单由桌面外部呈现，不冻结动作。
- 主宠物拖入另一块屏幕后在该屏幕活动；显示器移除或工作区变化时重新约束宠物位置。
- 飞扑裂纹是短暂覆盖效果，整个裂纹窗口不接收鼠标输入；宠物窗口仅有实际绘制区域接收点击。

## 局域网网络面板

协议和连接生命周期详见 [NETWORK_DESIGN.md](NETWORK_DESIGN.md)。

通过右键或托盘菜单的“网络面板…”进入，手动勾选“开启网络服务”。每次启动默认关闭，仅打开面板不会联网；关闭面板后，已开启的服务继续运行。关闭开关或退出程序会释放所有监听和连接。

- UDP **21012** 每 10 秒广播发现同一 IPv4 子网内的设备，TCP **21012** 握手后保持一条双向长连接。双方都需要开启服务。
- 面板显示设备名、IP、端口、实体数量/上限、版本、连接状态及最后通讯时间。多网卡发现按设备 ID 去重。
- **应用版本号必须完全一致，且网络协议版本兼容，才能建立互联和派遣。** 不匹配的设备仍能扫描到，显示“版本不匹配，无法互联”；未携带版本号的旧客户端显示“版本未知，无法互联”。刷新不会绕过校验，握手会再次核对。
- 应用版本统一来自 `CMakeLists.txt` 的 `project(... VERSION ...)`（当前 `0.2.0`），同时用于命令行 `--version` 和网络报文。发布新版本时更新此处并重新构建。
- “立即刷新”重新发现设备、查询已有连接资料并尝试重连，不拆掉健康连接。数量及上限变化最多每秒推送一次，仅更新资料显示。
- 每 10 秒心跳；静默失联约 30 秒断开，已收到断开通知则立即反映。主动连接端以 1～30 秒退避重连，120 秒无有效通讯的设备移出列表。
- 端口占用时显示错误并回滚整个启动操作。仅接受参与网卡直接连接子网内的 IPv4 来源，局域网 socket 使用直连，不经过系统代理。
- 最多保持 64 个已连接对端；支持下述自有实体派遣，不包含公网发现、认证或加密。仅用于可信局域网。

设备随机 ID 保存在 `network-device-id.dat`，与好感度存档位于同一目录；会话 ID 每次开启重新生成。不要把同一设备 ID 存档复制给不同机器。防火墙需允许 TCP/UDP 21012，路由器的客户端隔离也可能阻止发现；程序不会修改这些设置。已在两台 Ubuntu 24.04 X11 实体设备上验证局域网派遣与断线恢复；Windows 已通过编译，尚未完成运行验收。

### 派遣与召回

双方开启网络服务后，在“蟑螂列表…”选择一只或多只普通实体，点击“派遣…”选择目标。主实体不能派遣。来源端保留实体和行为计算，接收端仅显示；派出实体继续占来源端上限，访客不占接收端本地上限（访客另限 144 只）。

来源端可以重命名、播放投喂动画和高亮，支持单只“召回”及“全部召回”。接收端列表显示只读访客，窗口鼠标穿透。命名过的实体保留名称，未命名访客显示“来源主机名 #编号”。初版默认进入目标主屏幕。

短断线暂停相关实体和访客画面，保留 **30 秒宽限期**，重连核对成功后继续运行；超时返回来源端。静默断流约 3 秒后判定，因此从实际断流到回收通常约 33 秒。断线期间主动召回可能短暂同时显示；对端恢复或超时后清除。程序/服务重启不恢复旧派遣。网络接口暂时消失时自动等待恢复，无须立即重新打开开关。

当前不实现断线临时接管或访客本地交互。协议及边界说明见 [DISPATCH_DESIGN.md](DISPATCH_DESIGN.md)。

## 数据与平台边界

好感度和轮转日志保存在 Qt 的用户数据目录，Ubuntu 默认是 `~/.local/share/Pettime/Pettime/`。可以通过 `--data-dir /path/to/data` 指定其他目录。存档使用原子替换；保存失败不会结束程序，内存进度保留，30 秒后自动重试，也可从菜单重试。Windows 首次运行时会尝试导入 `%LOCALAPPDATA%/XiaoqiangPet/affinity.dat`，不修改旧存档。

数量上限存于同目录的 `population-limit.dat`，保存失败时本次运行仍生效，可重新打开数量上限菜单重试。实体列表和命名不写入存档。

单实例锁和本地通信按用户数据目录及会话标识隔离。传递同一个 `--data-dir` 的重复启动会召回该会话中的实例。

本轮支持 **Ubuntu X11**。程序在原生 Wayland 后端会明确提示限制并退出，因为常见 Wayland 桌面不允许普通应用随意定位顶层窗口。可以在具备 XWayland 的环境尝试 `QT_QPA_PLATFORM=xcb ./build/pettime`，但这不等于承诺 Wayland 下鼠标追逐等功能完整。Windows、其他 Linux 窗口管理器、混合 DPI 多屏和 macOS 尚未完成实机验证。

## 测试与动作导出

```bash
ctest --test-dir build --output-on-failure
./build/pettime --export --output /tmp/pettime-frames
./build/pettime --smoke --output /tmp/pettime-smoke
./build/pettime --smoke --smoke-pets 72 --duration 6 --output /tmp/pettime-smoke-72
```

- `network_tests` 覆盖发现、握手、长连接、刷新、推送、心跳、重连、协议校验及面板开关。长时间和实际网卡测试命令见 [VALIDATION.md](VALIDATION.md)。
- 自动化测试覆盖喂食、动作暂停、成长、追逐概率、分裂上限、队列排空、屏幕约束、存档错误、单实例召回和崩溃恢复。
- `--export` 默认使用 offscreen 后端，导出全部九组动作帧、序列图和背景对照图，不会召回已有桌宠。
- `--smoke` 默认运行六秒，自动演示一次飞扑，输出 `smoke.json` 和 `live-buffer.png`，失败返回非零退出码。测试存档放在输出目录的 `run-data/`，不读取或覆盖普通运行的好感度。
- `--smoke-pets` 支持 1–72，`--duration` 支持 3–120 秒。输出更新耗时仅涵盖应用的更新、图像准备与调度，不包括合成器的完整显示耗时。

Linux 构建还提供显式运行的 X11 输入测试（需要 X11/XTEST 运行库），会短暂显示测试背景窗口并移动鼠标：

```bash
QT_QPA_PLATFORM=xcb ./build/desktop_probe
```

该测试验证真实窗口系统中的点击穿透、不抢焦点、拖动、双击和裂纹输入穿透，不自动加入 CTest，以免常规测试操作用户桌面。测试环境必须允许访问显示服务；单实例测试还需要本地套接字权限。

## 代码结构

| 文件 | 职责 |
|---|---|
| `PetModel` | 无窗口依赖的行为状态、时间、移动、喂食及成长 |
| `SwarmController` | 统一实体表、稳定编号、主实体保护、群体更新、分裂队列及动态数量上限 |
| `AnimationLibrary` | 共享动作缓存、PNG 图集处理、程序绘图及帧导出 |
| `PetWindow` / `CrackWindow` | 透明窗口、输入区域、拖动和裂纹显示 |
| `ApplicationController` | 更新调度、菜单、托盘、屏幕变化及窗口生命周期 |
| `NetworkService` / `NetworkPanel` | 局域网发现、握手长连接、保活重连与设备面板 |
| `SettingsStore` / `SingleInstance` | 存档与日志、单实例及召回 |
| `tests/` | 逻辑回归与独立桌面输入测试 |

图片生成算法、动作参数及原素材来自上游，Qt 与 GDI+ 的抗锯齿效果可能略有不同。本次同时修正了旧版首次分裂实际产生 11 只、上限漏算主宠物、暂停时动作帧与状态计时不同步、存档异常退出的问题。

### 手动控制非主实体

在“蟑螂列表”中单选自己的非主实体，点击“开始控制”，使用 **WASD 或方向键**移动。
支持斜向移动，松开停止；面板内的方向键不会切换选中行。主实体、别人派来的访客和派遣交接中的实体不能手动控制。

本地实体和已派遣的实体都支持控制；派遣实体仍由原客户端计算运动，目标客户端仅渲染，受现有网络同步频率和延迟影响。
控制期间暂停自主行走，保留成长；“播放投喂动画”会暂时停止移动，动画结束后继续接受控制，“高亮定位”不影响移动。

面板失焦或打开重命名对话框时清除按键，重新聚焦后需重新按键。
停止控制、切换选择、关闭面板、派遣／召回或实体删除时退出控制；正常退出后恢复自主行为。
派遣断线时结束本次手动控制并冻结实体，沿用 30 秒重连宽限期，恢复连接后需重新点击“开始控制”。
